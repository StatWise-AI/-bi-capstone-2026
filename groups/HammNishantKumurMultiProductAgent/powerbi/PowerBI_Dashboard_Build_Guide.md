# Power BI Dashboard Build Guide — Matching the Streamlit App

This replaces the previous, thinner Power BI setup guide. It covers what was actually
investigated and built after the request to make Power BI show the same analysis as
Streamlit, not just raw exported tables.

## What was investigated first, honestly

The direct ask was to have Power BI "exported directly" with the dashboard already
built, rather than a data export you assemble into charts yourself. Before falling
back to a manual guide, I investigated whether this is now actually possible: Power BI
has a newer project format, **`.pbip`**, that stores a report as plain text/JSON files
(the **PBIR** format for the report, **TMDL** for the semantic model) instead of one
sealed binary `.pbix` — and Microsoft explicitly documents PBIR as designed to allow
"modifications from non-Power BI applications." That is a genuinely different, more
open situation than `.pbix`, which no tool can author at all.

**Where this ran into a real limit**: reference material on `.pbip` internals flags
that several files in a real project — `report.json`'s Desktop-version-specific theme
references, the `.platform` files' GUIDs, the base theme resource files — are
generated by Power BI Desktop itself and are described as "impractical to replicate
manually." On top of that, **I have no Power BI Desktop available to actually test
whether a hand-authored project opens correctly** — and shipping a full project file
that might silently fail to load, with no way for me to have verified it, seemed like
a worse outcome than being upfront about the boundary and giving you something that
reliably works.

**What I did instead, in order of how much I'd trust each piece:**

1. **A safe, real shortcut for the measures** (do this first — Part 1 below)
2. **The semantic model as TMDL files**, provided as a reference/experimental package
   (Part 2) — genuinely generated against your actual data schema, but untested
   end-to-end
3. **A complete page-by-page visual build guide** for the report itself (Part 3) —
   the guaranteed-to-work path, since hand-authoring the visual layer's JSON is the
   part I trust least without a way to verify it

---

## Part 1: The safe shortcut — bulk-create every measure at once

Power BI Desktop has a real, current feature called **TMDL view**, which lets you
paste a script directly into an *already-open, already-valid* semantic model to
create or update several objects at once — a legitimate, documented alternative to
typing each measure into the "New Measure" dialog one at a time. This sidesteps the
whole "will a hand-built project file even open" risk, because you're pasting into a
model Power BI Desktop already built and is already running.

1. Do your normal **Get Data → Excel Workbook** import of
   `EU_Diesel_PowerBI_Data_Model.xlsx` (Fact_DieselPrice + Dim_Date), and build the
   `Dim_Date[Date]` → `Fact_DieselPrice[Date]` relationship — exactly as in the
   original setup guide.
2. Go to **File → Options and settings → Options → Preview features**, check
   **TMDL view**, and restart Power BI Desktop.
3. Open **TMDL view** (it now appears as a tab/panel).
4. Open `measures_tmdl_view_script.tmdl` (provided alongside this guide) in any text
   editor, copy its contents, and paste them into TMDL view.
5. Click **Apply changes** (or the equivalent confirm action in your Desktop version).
   All 9 measures — including `WoW Change EUR`, `YoY Pct Change`, `Forecast End Price`,
   and a `Backtest Best Method` measure that reads off the `Backtest_Results` sheet —
   are created in one step.

If Power BI Desktop's parser rejects anything, it will tell you exactly which line and
why — a normal, self-correcting edit, not a silent failure.

## Part 2: The semantic model as TMDL (reference / experimental)

`Barrl_SemanticModel_TMDL_reference.zip` contains a generated `.SemanticModel` folder
— `Fact_DieselPrice.tmdl` and `Dim_Date.tmdl` with every column and all 9 measures,
`relationships.tmdl`, `model.tmdl`, `database.tmdl` — built directly from your actual
export schema, with real generated lineage-tag GUIDs.

**This is not a complete, double-click-to-open PBIP project** — there's no `.Report`
folder (the part flagged as unsafe to hand-author above), so there's nothing for a
top-level `.pbip` pointer file to correctly point at yet. Treat this zip as a
reference implementation: if you want to experiment, the way to actually use it is to
first create a minimal PBIP project yourself in Power BI Desktop (**File → Save As →
Power BI Project (.pbip)**, after enabling that preview feature too and building even
a trivial one-page report), then replace that project's own `.SemanticModel/definition`
contents with these files and reopen via the `.pbip` file. If Power BI Desktop
complains, it will name the exact file and line — treat that as a debugging starting
point, not a sign the whole approach failed.

For getting the measures into a model you're already using, Part 1 is the
recommended path — this zip is here for anyone who wants to go further.

## Part 3: Building the report pages (the reliable path)

One Power BI page per Streamlit tab. Use the measures from Part 1 throughout.

### Page 1 — Trend & Forecast (mirrors the Streamlit "Trend & forecast" tab)

- **Slicer**: `Fact_DieselPrice[Country]` and `Fact_DieselPrice[Product]` (or hide
  this page's filters behind a single "Country/Product" slicer pair at the top)
- **4 KPI cards**: `[Latest Price With Tax]`, `[WoW Change EUR]`, `[Latest Tax Share]`,
  `[Forecast Change Pct]`
- **Line chart**: X = `Dim_Date[Date]`, Y = `Fact_DieselPrice[PriceWithTax_EUR_per_1000L]`.
  Add `PriceWithTax_Lower80` and `PriceWithTax_Upper80` as two more line series (or a
  band via a combo visual) — filter the visual's tooltip/legend so forecast rows
  render as a dashed style if your Desktop version supports conditional line formatting.
- **Slicer**: a relative date filter on `Dim_Date[Date]` ("last 2 years") so the
  chart doesn't default to overwhelming detail.

### Page 2 — Tax Decomposition

- **Line/area chart**: `PriceWoTax_EUR_per_1000L` vs. `TaxAmount_EUR_per_1000L` over
  `Dim_Date[Date]`
- **Line chart**: `TaxSharePct` over time — this is the "36–65%" (EU-aggregate) or
  per-country swing discussed in the project write-up

### Page 3 — Model Comparison

- Import `Backtest_Results` as its own table (not related into the star schema — it
  has no date/key to join on)
- **Table visual** of `Backtest_Results`, conditional-formatted so the lowest MAE row
  is highlighted (matches the Streamlit app's highlighted-row behavior)
- **Card**: `[Backtest Best Method]`

### Page 4 — AI Briefing (closest equivalent)

The Streamlit briefing is generated live by a model call — Power BI has no live LLM
call built in, so this page shows the **latest generated snapshot**, clearly labeled
as such, rather than pretending it updates itself:

- Export the current briefing text from the Streamlit app (the "AI briefing" tab
  already shows it — copy it) into a new column or a one-row lookup table, e.g.
  `Briefing_Snapshot(Country, Product, GeneratedDate, BriefingText)`
- **Card or text box visual** bound to `BriefingText`, with a caption: *"Snapshot
  generated {GeneratedDate} — refresh this manually; it does not regenerate live."*

### Formatting, per the same rules as the original setup guide

- Star schema only — don't relate `Backtest_Results` into the model
- Measures, not calculated columns, for anything aggregated dynamically
- 4–6 visuals per page maximum, KPI cards top-left
- One consistent color for actual data, a second clearly distinct one (or dashed
  style) for forecast rows

## Keeping this in sync with the app

Same two-click workflow as before: **"Refresh Power BI export"** in the Streamlit
sidebar regenerates the Excel file (now also reflecting the hybrid GBM/SARIMAX model
per combination — see the app's model comparison tab), then **Home → Refresh** in
Power BI Desktop picks up the new numbers. The report *pages and visuals* you build in
Part 3 don't need rebuilding when the data refreshes — only the underlying data
changes, same as any normal Power BI report.
